# FeatherMorphClient 26.1 → 26.2 移植说明

本文档记录把上游 `26.1/main` 移植到 **Minecraft 26.2 / Fabric** 时，逐项做了哪些改动，以及几个**只在实机运行时才暴露**的坑（mixin 目标不会在编译期报错，这些只有进游戏才会发现）。供后续版本移植或二次开发参考。

- 移植基线：`NiFeather/FeatherMorphClient` 默认分支 `26.1/main`
- 目标：Minecraft 26.2、Fabric Loader 0.19.5+、Java 25

---

## 一、构建配置

| 项 | 26.1 | 26.2 |
| --- | --- | --- |
| `minecraft_version` | `26.1` | `26.2` |
| `fabric_version` | `0.144.3+26.1` | `0.161.0+26.2` |
| `fabric_loader_version` | `0.18.5` | `0.19.5` |
| `modmenu_version` | `18.0.0-alpha.8` | `20.0.3` |
| `clothconfig_version` | `26.1.154` | `26.2.155` |
| EMF / ETF / EntityCulling | 26.1 版 | `3.3.8` / `7.2.4` / `1.11.2` 的 26.2 版 |
| Fabric Loom | `1.15-SNAPSHOT` | `1.17.21`（Fabric 官方 26.2 文档推荐 Loom 1.17） |
| Gradle wrapper | `9.2.1` | `9.7.1` |

编译工具链仍是 **Java 25**（26.2 要求）。注意 Loom 1.18+ 强制要求**运行 Gradle 的 JVM** 也是 Java 25，而 Loom 1.17 只要 21+，用 JDK 21 跑 Gradle + JDK 25 做工具链的组合最稳。

## 二、原版 API 变更与对应修改

### 1. 注册常量搬家：`EntityType` → `EntityTypes`

原版把实体类型常量移到了 `net.minecraft.world.entity.EntityTypes`，并删除了 `EntityType.byString(String)`：

- `EntityType.<常量>` → `EntityTypes.<常量>`（`ClientDisguiseProperties`、`AnimHandlerIndex`、`VanillaAnimationProvider`、`ModelWorkarounds`、`DisguiseSyncer`、`PlayerRenderHelper`、`CommonEventProcessor`、`DisguiseMeta`、`EntityCache` 等，约 100 处）。
- `EntityType.byString(id)` 的三处调用改为注册表查询：
  - `EntityCache`、`VanillaDisguiseProvider`：`Identifier.tryParse(...)` + `BuiltInRegistries.ENTITY_TYPE.getOptional(...)`，保持「非法/未知 ID 返回空」的原有语义；
  - `DisguiseMeta`：`BuiltInRegistries.ENTITY_TYPE.getOptional(Identifier.parse(...)).orElseThrow()`。
- 注意 **`EntityType.getKey(EntityType)` 仍然存在**，不要一并改名。

### 2. Gui / Hud 重组

`Minecraft` 上的 GUI 相关字段与方法被搬进 `net.minecraft.client.gui.Gui`（HUD 再拆到 `Hud`）：

| 26.1 | 26.2 |
| --- | --- |
| `Minecraft.getInstance().screen` | `Minecraft.getInstance().gui.screen()` |
| `Minecraft.getInstance().setScreen(s)` | `Minecraft.getInstance().gui.setScreen(s)` |
| `Minecraft.getInstance().getToastManager()` | `Minecraft.getInstance().gui.toastManager()` |
| `Minecraft.getInstance().options.hideGui` | `Minecraft.getInstance().gui.hud.isHidden()` |
| `Minecraft.getInstance().gameRenderer.getMainCamera()` | `Minecraft.getInstance().gameRenderer.mainCamera()` |

### 3. 渲染：`MultiBufferSource` 被特性渲染系统取代

26.2 删除了 `MultiBufferSource` 接口（连同 `RenderBuffers#bufferSource()`、`OutlineBufferSource` 等），改由 `SubmitNodeCollector` / `OrderedSubmitNodeCollector` 提交渲染节点。

- `PlayerRenderHelper#submitCrystalBeamIfPossible(...)` 去掉 `MultiBufferSource` 形参（方法体本来就只用 `SubmitNodeCollector`），调用方 `WorldRendererMixin` 相应删掉 `renderBuffers.bufferSource()`。
- `OrderedSubmitNodeCollector#submitNameTag` 少了一个 `int` 参数（26.2 签名：`PoseStack, Vec3, int, Component, boolean, int, CameraRenderState`）。
- `EnderDragonRenderer.submitCrystalBeams(...)`、`LevelRenderer.submitEntities(PoseStack, LevelRenderState, SubmitNodeCollector)` 在 26.2 仍存在，mixin 目标不变。

### 4. 其它原版 API

| 26.1 | 26.2 | 位置 |
| --- | --- | --- |
| `net.minecraft.util.Tuple`（可变 A/B 对） | 已删除 → 改为文件内私有类 `MorphLocalPlayer.ProfileRequest` | `MorphLocalPlayer` |
| `Mob#setBodyArmorItem(ItemStack)` | 已删除 → `setItemSlot(EquipmentSlot.BODY, stack)` | `DisguiseSyncer` |
| `net.minecraft.world.entity.monster.Slime` | 包移动 → `...monster.cubemob.Slime` | `SlimePropertyCollection` |

| 依赖 | 变更 | 位置 |

| EntityCulling 1.11.2 | `dev.tr7zw.entityculling.versionless.access.Cullable` → `dev.tr7zw.entityculling.access.Cullable` | `EntityCullingCompatibilityHandler` |

## 四、只有运行期才会暴露的坑（重点）

mixin 的 `@Shadow` / 注入目标**只在运行时校验**——编译通过不等于能进游戏。移植过程中实际踩到下面 5 个：

### 1. `Minecraft#setScreen` 已删除、`screen` 字段已移走

`MinecraftClientMixin` 原本 `@Shadow` 了 `Minecraft.screen` 并在 `Minecraft#setScreen` 上注入。26.2 两者都不在 `Minecraft` 里了，启动即崩：

```
@Shadow field screen was not located in the target class net.minecraft.client.Minecraft
```

处理：删掉该 shadow 与注入，新增 `GuiMixin`（`@Mixin(Gui.class)`）挂在 `Gui#setScreen` 的 `HEAD`（此处字段仍是旧界面），并在 `feathermorph_client.mixins.json` 的 client 列表登记。

### 2. `ItemInHandRenderer#renderHandsWithItems` 改名

26.2 改名为 `submitHandsWithItems(float, PoseStack, SubmitNodeCollector, LocalPlayer, int)`，`ItemInHandRendererMixin` 里的 `@ModifyVariable(method = "renderHandsWithItems")` 需要同步改名。

### 3. 客户端自建的伪装实体没有实体 ID

26.2 的 `Entity#getId()` 变成了会抛异常的检查（26.1 只是返回 0）：

```java
public int getId() {
    if (this.id == 0) throw new IllegalStateException("Tried to access entity ID before ID assignment");
    return this.id;
}
```

本模组为了让伪装可见，会在客户端自建「伪装实体」（`EntityCache#getEntity` 里的 `EntityType#create(...)` / `MorphLocalAvatar` / `MorphLocalPlayer`），它们从不经过服务端分配 ID，`id` 恒为 0 → 渲染时必崩（预览界面则被 `catch` 吞掉，表现为「模型一直加载不出来」）。

处理：在 `EntityCache` 创建实体后自行发号，从 `-1` 开始递减（既保证非 0，也保证不会与服务端分配的、恒为正的 ID 撞号）：

```java
private static final AtomicInteger nextSyntheticEntityId = new AtomicInteger(-1);
private static int allocateSyntheticEntityId() { return nextSyntheticEntityId.getAndDecrement(); }
```

### 4. `makeBoundingBox()` 被拆成两个重载

26.2 的 `Entity`：

```java
protected final AABB makeBoundingBox() { return this.makeBoundingBox(this.position); }   // setPos() 调用
protected AABB makeBoundingBox(Vec3 pos) { ... }                                          // 使用缓存的 dimensions
```

调用分布：`setPos` 走无参版本，但 **碰撞求解 `collidedWithShapeMovingFrom` 与 `checkInsideBlocks` 直接调用 `Vec3` 版本**。只拦截无参版本会让同一 tick 内出现两个不同的碰撞箱（自己和自己打架 → 贴墙卡住/来回抖动）。

处理：改为拦截所有调用都会经过的 `Vec3` 版本，并使用**调用方传入的位置**（碰撞求解传的是目标位置，不能用 `this.position`）。

### 5. 碰撞箱尺寸的 SCALE 口径必须和服务端一致

服务端插件（`VanillaDisguiseProvider#tryModifyPlayerDimensions`）取箱子的方式是「新生成一个伪装实体、读它的原始 AABB」，即**不含玩家 SCALE 属性**；而 `LivingEntity#getDimensions(pose)` 会把实体自身的 `SCALE` 乘进去，本模组的 `DisguiseSyncer` 又会把玩家的 SCALE 同步给伪装实体（为了按玩家体型渲染）。两者叠加 → 客户端箱子比服务端小一圈 → 能挤进服务端不允许的位置 → 被拉回 → 撞墙抖动。

处理：客户端镜像碰撞箱时改用**不含 SCALE 的原始尺寸**（`LivingEntity#getDefaultDimensions`，通过 `LivingEntityAccessor#callGetDefaultDimensions` 访问），并固定用 `Pose.STANDING`（服务端用的是 `EntityDimensions.fixed(...)`，本身就是与姿势无关的固定箱）。

> 相关：服务端设的眼睛高度是 `伪装高度 × 0.85`，客户端用的是伪装实体**经过 SCALE 后**的眼睛高度（与按玩家体型渲染出来的模型一致），因此客户端相机高度会略低于服务端认为的眼位——这是刻意的（观感上相机贴着实际渲染出来的模型），没有改动。

## 五、已知现象与备注

1. **refmap 警告**：Loom 1.17 起 mixin 注解处理器默认关闭，jar 里不再生成 `feathermorph_client.refmap.json`，而四个 mixin 配置里仍保留 `"refmap"` 字段（与上游一致），实机启动会打印 3 条 `Reference map ... could not be read` 警告——**非致命**，其他模组（如 entityculling）也有同样警告。
2. **paperdoll 兼容**：`feathermorph_client.paperdoll_hack.mixins.json`（`required: false`）保留，但 paperdoll 依赖自上游起已被注释，未做 26.2 适配。
3. **NeoForge**：上游自 26.1 起已在 `settings.gradle.kts` 中注释 `include("neoforge")`，本移植同样只针对 Fabric。
4. **运行时验证程度**：已在实机验证伪装显示、预览界面、解除伪装、相机高度、碰撞箱行为；`@ModifyVariable` 的 `ordinal` 语义（依赖目标方法局部变量表顺序）属静态无法校验的部分，若有异常请带上日志反馈。
